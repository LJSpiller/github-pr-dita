Understanding the Pull Request Lifecycle

A pull request proposes changes from a working branch to the primary repository branch, enabling peer review and automated testing before integration.

In GitHub, pull requests serve as the primary mechanism for code and documentation review.

A pull request progresses through three primary stages:

  • Draft State: Work in progress; automated checks run, but peer review is not required.
  • Open for Review: Ready for peer review and automated continuous integration status checks within the target 24 hours SLA window.
  • Approved & Merged: Required reviewers approve changes, all automated status checks pass, and code merges into the target branch.
